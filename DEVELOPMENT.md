# USB PPPS Hub Development

The schematic, PCB and JLCPCB files are generated by the scripts in `scripts/`. It is recommended to change the scripts, not the files in KiCad, because regenerating overwrites KiCad edits. The design is in [spec.md](spec.md).

## Setup

Supported on macOS and Linux.

Install:

- [KiCad 9](https://www.kicad.org/download/)
- Python 3 and Git
- Poppler, for the PNG renders (`brew install poppler` on macOS, `poppler-utils` on Linux)

The scripts use KiCad's default install, and `kicad-cli` from the PATH if it's present. If your KiCad is elsewhere, set these environment variables:

| Variable | Path |
| --- | --- |
| `KICAD_CLI` | `kicad-cli` |
| `KICAD_PYTHON` | Python with KiCad's `pcbnew` module |
| `KICAD9_SYMBOL_DIR` | KiCad's stock symbol libraries |
| `KICAD9_FOOTPRINT_DIR` | KiCad's stock footprint libraries |

`scripts/kicad-python` runs a script using KiCad's Python.

## Generating

```bash
scripts/generate.sh
```

This writes:

- the KiCad project and a schematic PDF to `kicad/`
- the JLCPCB files to `jlc/`
- the EEPROM image to `usb-ppps-hub-eeprom.bin`

It stops if there are uncommitted changes or untracked files. To see uncommitted changes in KiCad, run `scripts/check_pcb.sh build` and open `build/usb-ppps-hub.kicad_pro`.

Change ERC exclusions and other project settings in `kicad-src/usb-ppps-hub.kicad_pro`.

## Changing the Schematic

The schematic is generated by `scripts/usb_hub.py`. After changing the script, check the schematic:

```bash
scripts/check.sh build
```

This generates the schematic in `build/`, runs ERC and compares the netlist with `scripts/expected_nets.py`. It prints any netlist differences and ERC violations, and a `LAYOUT` line for overlapping symbols or text and for wires that cross them. The sheet is rendered to `build/sheet-1.png` at 100 dpi, or at `DPI` if set.

ERC violations excluded on a part reappear if the part moves or its reference changes.

`expected_nets.py` is the netlist written by hand from spec.md, separately from `usb_hub.py`. Update it when you change a connection, so a mistake in `usb_hub.py` appears as a netlist difference.

To see part of the sheet close up:

```bash
scripts/crop.sh build hub 50 5 100 60
```

This writes `build/hub.png` at 220 dpi, from x0 y0 to x1 y1 in units of 2.54 mm from the sheet's top left.

## Changing the PCB

The board is generated by `scripts/usb_hub_pcb.py`. Board size, connector pitch, and part and silkscreen positions are parameters at the top of the script. Tracks are built from pad positions, so a passive's footprint size can change without routing changes. The stackup is JLC04161H-7628 and the design rules are JLC's 4-layer limits.

Check the board:

```bash
scripts/check_pcb.sh build
```

This generates the schematic and board in `build/`, runs DRC with schematic parity and prints the violations, unconnected items and parity problems. It renders at 300 dpi or at `DPI` if set:

- the top layers to `build/top.png`
- the bottom copper to `build/bottom.png`
- the In2.Cu power plane to `build/power.png`

Generating the board also prints:

- `PAIR` lines with the length of each USB pair's tracks and the difference within the pair
- `STITCH` with the number of GND stitching vias placed
- `ANGLE` for a track segment that isn't horizontal, vertical or at 45°
- `ACUTE` for a track bend sharper than 90°
- `SILK` for a part with silkscreen outside the board outline
- `VIAPAD` for a via that overlaps a pad
- `UNPLACED` for any part without a position

Ignore DRC warnings that the USB-C connector footprints don't match the library.

To see part of a render close up:

```bash
scripts/crop_pcb.sh build top 30 10 45 30
```

This writes `build/top-crop.png` at 1200 dpi, or at `DPI` if set, from x0 y0 to x1 y1 in mm from the board's top left. The second argument is `top`, `bottom` or `power`.

When the board changes, update the board render in the README after running `generate.sh`:

```bash
scripts/render.sh
```

## Version, Commit and Source Location

The version in `VERSION` is printed in the schematic's title block and on the silkscreen.

`generate.sh` sets the commit on the silkscreen to the short hash of HEAD.

https://piers.rocks on the left edge is `SOURCE_LOCATION` in `scripts/usb_hub_pcb.py`. The [LICENSE](LICENSE) and [NOTICE](NOTICE) require it remain on the PCB.

## EEPROM Image

The image is built from the EEPROM contents table in [spec.md](spec.md#hub-configuration).

## JLCPCB Files

`generate.sh` runs `scripts/jlc.py`, which writes the zipped Gerbers and drill files, the BOM and the CPL to `jlc/`.

DNP parts and the mounting holes aren't in the BOM or CPL. `jlc.py` prints `NOLCSC` for any BOM row without an LCSC part number.

If a part is rotated or shifted in JLC's preview, add a correction for its LCSC part number to `CORRECTIONS` in `scripts/jlc.py`.

## Validation

```bash
scripts/check_all.sh build
```

This runs the schematic and board checks and builds the EEPROM image. CI runs it with KiCad 9.0.7.

## Releasing

1. Set the version in `VERSION`.
2. Date the version's section in [CHANGELOG.md](CHANGELOG.md), for example `## v0.1.0 - 2026-10-21`.
3. Commit.
4. Tag the commit with the version and push the tag.

The Release workflow creates a GitHub release with the changelog section as its notes. The release contains:

- `usb-ppps-hub-gerbers.zip`, with the tag's commit on the silkscreen
- `usb-ppps-hub-bom.csv` and `usb-ppps-hub-cpl.csv`
- `usb-ppps-hub-eeprom.bin`
- `usb-ppps-hub-schematic.pdf`
- `usb-ppps-hub-kicad.zip`, the KiCad project with LICENSE and NOTICE

`scripts/release.sh v0.1.0` writes the same files to `build/release/`.

## Parts

Each passive's footprint, LCSC part number and MPN are set by value in `PASSIVES` in `scripts/usb_hub.py`. A second source's LCSC part number goes in `ALTS` and appears in the schematic's `LCSC alt` field.

The USB-C connector's footprint is in `kicad-src/usb-ppps-hub.pretty` and the TLV803S symbol in `kicad-src/usb-ppps-hub.kicad_sym`. All other footprints and symbols come from KiCad's stock libraries. If the schematic needs a new stock symbol library, add it to `kicad-src/sym-lib-table` or ERC fails in CI.

## Shipping
